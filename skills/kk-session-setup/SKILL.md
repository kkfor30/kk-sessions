# kk-session-setup

## 输入

- 本目录的 `workspace-map.template.md`：地图模板。「标题」「嵌套会话」「跟进」三节是通用规则，原样保留；「分区」表和其后的说明是示例，要换成用户自己的。
- 六个动作的做法见 kk-session-route 的「六个动作」「适配」两节，这里用列出全部会话、列出和新建分区。

## 流程

1. **检查现状**：`~/.agent-rules/workspace-map.md` 已存在时，先列出其中的分区，问用户选哪种：
   - **沿用地图**（地图是在另一个 Agent 里生成的，这个 Agent 第一次用）：不改地图，直接跳到第 6 步，在当前 Agent 的侧栏建好同名分区。
   - **补几个分区**：在原文件上改，不重写，然后第 6 步。
   - **重新规划**：从第 2 步开始。
2. **收集线索**（只看元数据，不读聊天记录）：
   - 列出全部会话（含已归档），取标题、工作目录、已有分区。
   - 把工作目录按上级目录归并，统计每个目录下有多少会话；对出现较多的根目录，列一层子目录。
3. **拟分区**：按"领域"而不是"做哪类事"分，通常 4 到 7 个；每个分区一个颜色 emoji（🔴🟠🟡🟢🔵🟣🟤⚫⚪ 等）加 2 到 4 个字的名字，名字用用户会话里自己的叫法。分区只从这一步收集到的线索推出来，不照搬模板或其他文档里现成的分区表。每个分区写清：
   - 产物目录：优先用会话里已经在用的目录；需要按主题再分的写成 `<根目录>\<主题>\`。
   - 放什么、判定线索：从会话标题里提炼用户自己的说法。
   - 固定加一个 `📦 杂项` 兜底（一次性问答、电脑设置），目录选一个已有的杂项目录或建议新建一个。
   - 用户常试用开源项目时，加一个试用目录 `<项目根>\_试用\<名称>-<YYYYMMDD>\`。
4. **和用户确认**：用一张表给出分区、产物目录、放什么、判定线索，并说明每个分区大约覆盖了哪些现有会话。用户改完明确确认后再写。
5. **写地图**：以模板为底，替换「分区」表和其后的说明，删掉模板说明那一行，用文件写入工具直接写到 `~/.agent-rules/workspace-map.md`，不要用 shell 或脚本拼接内容（Windows 路径里的 `\b`、`\n` 会被当成转义符）；写完读回分区表，核对路径一字不差。目录不存在就建。表里没出现的目录不建，等 kk-session-route 用到时再建。
6. **建分区**：先按 kk-session-restore 的「快照」一节存快照（已有就跳过），再在侧栏按地图名称建好所有分区，已有同名的跳过。
7. **收尾**：报告建了几个分区、地图写在哪；问用户要不要现在整理旧会话，要就转 kk-session-tidy。

## 边界

- 只写地图和建分区，不移动会话、不改标题、不移动或删除用户的文件夹。
- 会话很少（少于 5 个）时线索不够，按用户磁盘上已有的顶层目录拟几个起步分区让用户改，并说明以后可以再运行一次。
