# kk-session-route

## 输入

工作区地图：`~/.agent-rules/workspace-map.md`（分区、目录、判定线索、标题格式）。什么时候读见下面「流程」。

地图不存在时不归位：照常处理用户的请求，在回复最后用一句话说明还没初始化，问用户要不要运行 `kk-session-setup`。

## 六个动作

流程只用这 6 个动作，每个 Agent 怎么完成见下面「适配」：

| 动作 | 含义 |
| --- | --- |
| 取会话 ID | 拿到当前会话的 ID |
| 改标题 | 把当前会话标题设成指定文本 |
| 列出和新建分区 | 找到地图里的同名侧栏分区，没有就新建 |
| 移入分区 | 把当前会话放进该分区 |
| 切目录 | 把会话的工作目录换到目标目录 |
| 列出全部会话 | 取所有会话的标题、分区、目录、最后活动时间（kk-session-setup、kk-session-tidy 用） |

某个动作在当前 Agent 做不到时，统一降级：在回复里给出建议值（分区名、标题、目录），由用户手动操作。

## 流程

原则：**先处理用户的请求，归位放在本轮回复结束前完成**，不让归位挡在回答前面。按第一条消息分三种情况：

| 情况 | 回答前 | 回答后（本轮结束前） |
| --- | --- | --- |
| A. 一两句能答完的问题（问答、查东西、电脑设置） | 什么都不做，直接回答 | 改标题、归 📦 杂项；不建目录、不切目录 |
| B. 要产出文件的任务（方案、脚本、工具、剪辑） | 读地图、定目录、建目录和 README（一轮，和读其他文件并行） | 改标题、归区、切目录，放在同一轮发出 |
| C. 归属拿不准，或和地图里所有分区都对不上 | 不等用户，先按首选目录处理请求 | 末尾问一句归哪里（给出首选）；用户回答后的下一轮再完成归位，文件需要就整个移过去 |

### 回答前（只有 B、C 需要）

1. **读地图，定目录**：对照地图选分区和产物目录。需要具体主题的分区，列出该目录下已有子目录，能对上就用已有的；对不上再定一个新主题名。调研转正式选题、试用转正式项目时，整个文件夹移过去。读地图和列目录在同一条消息里并行发出。
2. **建主题目录和 README**：新主题当场建目录和 `README.md`（是什么、状态：想法、下一步），子目录用到时再建。
3. 之后本会话的产物一律写到目标目录的绝对路径（切目录要到下一轮才生效）。

### 回答后（本轮结束前，全部情况）

情况 A 此时才读地图；地图已经读过就不再读。侧栏工具是延迟加载的，用 ToolSearch 一次性加载。

1. **第一条消息**，并行发出：
   - **改标题**：`<类型emoji> <主题>｜<这次做什么>`，emoji 后 20 字以内；类型 emoji 只从地图「标题」表的 8 个里选。这轮结尾留下只有用户能做的事时，直接带上 ` ⏳`。
   - **列出分区**；快照目录里没有当前 Agent 的快照时，同时列出全部会话（含已归档），用于存快照（格式见 kk-session-restore 的「快照」一节）。
   - **切目录**（只有 B）：工作目录不在目标目录内时切过去。
2. **第二条消息**：需要时先写快照，再按需新建分区，最后移入分区。
3. **一句话说明**放在回复最后："已归到 🟣 内容制作，标题 `🔍 新品测评｜竞品拆解`"。做不到的动作在同一句里给出建议。

### 补漏

本轮被打断或出错导致没归位时，下一轮开头检查：标题还不是 `<类型emoji> <主题>｜…` 格式，就按上面「回答后」补做一次，只补一次。

### 新分区

和地图里所有分区都对不上（新的领域、新的长期项目）时，按情况 C 处理：末尾提议一个新分区，写明名称（颜色 emoji 加 2 到 4 个字）、产物根目录、判定线索。用户同意就把这一行加进地图「分区」表、在磁盘建根目录、在侧栏建分区，再完成归位；不同意就归到 📦 杂项。不要不问就建顶层目录。用户在哪个目录开的会话都可以，归位以地图为准。

## 标题锁定

- 主题第一次命名后锁定，之后不改。
- emoji 和｜后半段默认也不自动改。只有 kk-session-tidy 会对很长、阶段明显变化的会话提出改名建议，用户确认才改。
- 末尾 ` ⏳` 按地图「跟进」一节增减，这是唯一允许 Agent 自动改的部分。
- 置顶只由用户手动操作。

## 适配

有环境变量 `CODEX_THREAD_ID` 是 Codex；有 `mcp__ccd_*` 工具是 Claude Code 桌面端。都不是（如 Claude Code 命令行），六个动作全部降级为建议。

### Claude Code 桌面端

| 动作 | 做法 |
| --- | --- |
| 取会话 ID | 不需要，工具都接受 `"self"` |
| 改标题 | `mcp__ccd_session_mgmt__set_session_title`，`session_id: "self"` |
| 列出和新建分区 | `mcp__ccd_sidebar__list_sections` 找同名，没有就 `create_section` |
| 移入分区 | `mcp__ccd_sidebar__move_sessions`，`session_ids: ["self"]`；当前会话嵌在父会话下时会被拒绝，此时跳过，跟随父会话 |
| 切目录 | `mcp__ccd_directory__change_directory`（用户在卡片上批准一次；本轮结束后生效，本轮写文件用绝对路径） |
| 列出全部会话 | `mcp__ccd_session_mgmt__list_sessions` |

这些工具是延迟加载的，先用 ToolSearch 一次性加载再调用。

### Codex 桌面端

| 动作 | 做法 |
| --- | --- |
| 取会话 ID | 环境变量 `CODEX_THREAD_ID` |
| 改标题 | `mcp__codex_app__set_thread_title`（省略 `threadId` 即作用于当前会话） |
| 列出和新建分区 | `list_threads` 返回的 `sections[]` 找同名，没有就 `create_sidebar_section` |
| 移入分区 | `move_thread_to_sidebar_section({threadId, hostId: "local", sectionId})`，然后用 `list_threads` 回读：正式键 `codex:thread:local:<threadId>` 出现在目标分区的 `itemKeys` 里才算成功。首轮常只移进一个 `client-new-thread` 别名，没成功就在下一轮开头补做一次并再回读 |
| 切目录 | 不支持，降级：产物写到目标目录的绝对路径，回复里建议用户在侧栏把会话移到对应项目 |
| 列出全部会话 | `list_threads`（`mode: "history"` 分页），归档用 `list_archived_threads` |

## 边界

- 只在会话第一轮归位一次。之后话题变化不自动迁移，用户要求时再重新归位。
- 已由用户手动命名或手动放入分区的会话，不覆盖用户的选择。
- fork 或旁支会话：沿用父会话的主题，只换 emoji 和这次做什么，例如 `🐛 新品测评｜导出变慢排查`。主题已和父会话不同时，提醒用户在侧栏拆成顶层会话后再归区（Agent 只能拆自己启动的会话）。
