# kk-session-tidy

## 输入

- 工作区地图：`~/.agent-rules/workspace-map.md`（分区、标题格式、类型 emoji、嵌套规则、⏳ 规则）。先读它。
- 六个动作和各 Agent 的做法见 kk-session-route 的「六个动作」「适配」两节，这里只用其中的列出全部会话、改标题、列出和新建分区、移入分区。

## 流程

1. 列出全部未归档会话和分区，跳过当前会话。当前 Agent 不支持列出全部会话时（WorkBuddy），说明后结束。
2. 只看元数据（标题、分区、父会话、最后活动时间），不读聊天记录。逐个检查，只记录需要改的：
   - **标题格式**：不符合 `<类型emoji> <主题>｜<这次做什么>` 的，拟新标题；末尾已有的 ` ⏳` 保留。子会话沿用父会话的主题。
   - **阶段改名**：会话很长（活动跨多天或轮次很多）且｜后半段已明显不符合现在在做的事，拟一个新的 emoji 和后半段；主题不变。
   - **分区**：没有分区的，按地图拟分区。子会话跟父会话走，不单独移动。
   - **拆出**：子会话主题已和父会话不同的，列入"需要你手动拆出"，写明拆出后该去的分区。
   - **待推进**：列出标题带 ⏳ 的会话和最后活动时间，超过 7 天没动的标出来。用户说哪些已办完，就去掉那些标题末尾的 ⏳。
3. 用一张表列出建议：会话、改什么、理由（一句）。当前 Agent 做不到的改动（如 Z Code 的分区）标"需手动"。没有要改的就说"侧栏已整齐"。
4. 用户确认后执行；用户事先说了"直接改"就直接执行格式和分区类改动，阶段改名仍逐条等用户确认。执行后报告改了几处。

## 边界

- 不置顶、不归档、不删除：置顶由用户手动操作，归档交给应用。
- 主题锁定：任何改名都不改主题。不改用户手动取的、已符合格式的标题；不移动用户手动放好的分区。
- 地图里没有合适分区时，提议新分区名，等用户确认再建。
